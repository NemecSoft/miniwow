# 2026-10-22 · MiniWoW 工作日志

## M48 · 修「人走路重影 + 方向不对」（用户两次退单）

### 用户原话
> 「正常个鸡毛！人走路是重影的，方向也不对！你的检查方式不对，优化你自己的检查方式」

### 根因（三个独立 bug，都有实测数据）
1. **朝向公式在球面失效** —— `3d_godot_robot.gd` 的 `apply_rotation` 用
   `atan2(v.x, v.z) - parent.basis.get_euler().y`，这是世界 XZ 平面的 yaw 公式。
   球面上当地水平面 ≠ 世界 XZ 平面，实测 bot 偏差 **+142.3°**（背对运动方向跑）。
2. **bot 出生点用世界轴偏移** —— `bot_controller.gd` 的 `spawn_pos + Vector3(i*3,0,0)`
   + 平面地形探针 `get_height(x,0,z)`。实测 4 个 bot 挤在 **1.86~6.32m** 内
   （用户眼里的"重影"就是一坨叠在一起的人），且悬空 **2.42/3.86/5.62/7.80m**。
3. **远端玩家朝向从来没有同步** —— `_physics_process` 对非 authority 第 621 行直接 return，
   `_body.rotation.y` 在别人屏幕上永远是出生值。位置和 Run 动画都是同步的，
   所以看到"跑着动画却拧着身子"的复制人。

### 修复
- `3d_godot_robot.gd`：新增 `_local_yaw_for()`，把方向投影到**父节点 basis** 的切平面，
  `rotation.y = atan2(t·pb.x, t·pb.z)`。平面地图下父 basis 退化单位基 → 等价旧式，零回归。
- `bot_controller.gd`：出生点改**当地切平面黄金角散开**（`BOT_SPAWN_RADIUS=9`）
  → `Planet.snap_to_surface()` → `Planet.fit_ground(body, 0)`。
- `player.gd`：新增 `_net_body_yaw` RPC（`any_peer` + `unreliable_ordered`，10Hz 节流），
  只同步 body 的**局部标量 yaw**。校验 sender = authority 或服务器 1（bot 由服务器代发）。
- `bt_bot_move_to.gd`：`_face_velocity` 末尾代 bot 调 `_net_tick_body_yaw()`
  （bot 的 authority=900x，不走玩家的自动分发）。
- `planet.gd` `model_lowest_projection`：跳过 `is_visible_in_tree()==false` 的 mesh
  （否则 fit_ground 按隐形模型落地，看得见的人悬空）。

### 验收数据（tools/m48_body_probe.gd）
| 指标 | 修复前 | 修复后 |
|---|---|---|
| bot 朝向与运动方向偏差 | +142.3° | +1.4° ~ +10.0° |
| bot 悬空 | +2.42 / 3.86 / 5.62 / 7.80 m | -0.00 / 0.00 / 0.00 / 0.69 m |
| bot 出生间距 | 1.86 ~ 6.32 m | 22.6 ~ 53.8 m |
| 远端玩家 bodyY（按 A 转向后） | 恒 0.000（永不更新） | 0.296 → 1.569 → 1.571（与本地千分位一致）|
| 每个玩家可见模型分组 | — | 恒 = 1（RobotArmature 5 个 或 InfantryVisual 8 个，绝不共存）|

### 新工具
`tools/m48_body_probe.gd` + `.tscn`：支持 `--auto host/join` 双端。
输出 `VIS[玩家]`（重影判定）/ `BODY[玩家]`（模型开关）/ `ORI[玩家|阶段]`（朝向，`差` < 2°）。
host 端会自动等真人远端（排除 bot）再开拍，否则会拍成独角戏。

### 检查方式的三条硬规矩（已写入 docs §6.4）
1. 检查对象必须是"用户眼睛看到的那一份"（全部玩家，不只本地）
2. 必须判"视觉分组"（两套模型同可见 = 重影），不能只读开关属性
3. 必须制造可观测的状态变化（验朝向同步要按 A 转向 90°，只按 W 看不出问题）
